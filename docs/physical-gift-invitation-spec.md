# 原箱禮包贈禮邀請

日期：2026-10-06。來源：使用者同意私人邀請連結方案並要求實作。這是既有統一 QR 禮包的擴充；之前使用者接受的 SG-6／SE5-1 風險例外保持原紀錄。

## 驗收規則

| ID | 行為 |
| --- | --- |
| I1 | 卡片仍相同；收件人沿用現有登入／註冊，不新增手機或地址驗證。訂單與包裹仍屬購買者。 |
| I2 | 購買者可將尚未核銷的原箱 SHIPMENT 資格建立私人邀請，不能分享名片見面禮或他人資格。每箱仍一份資格。 |
| I3 | 有效邀請阻擋購買者自己領；領取前可撤回或產生新連結，舊連結失效。已領不能撤回、換收款人或再送。 |
| I4 | 持有連結且登入的人確認開盒時才歸戶，無聯絡方式驗證；先到先領。開啟網址、登入或 GET 預覽均不歸戶、不抽、不入帳。 |
| I5 | 私人連結不得繞過物流、取消／退回、活動暫停、預算或原政策版本；未送達與待補資不消耗邀請。 |
| I6 | 邀請領取、購買者領取、撤回／替換與並行領取使用原 budget／order 鎖；只一份原 claim、固定 recipient／wallet／draw／credit key／ledger。回應丟失及 worker 重啟仍回原結果。 |
| I7 | 不可猜測的 256-bit 隨機憑證在伺服器只保存 SHA-256 雜湊；前台分享網址以 fragment 搭配邀請 ID，讀入後移除 fragment，憑證留在本頁的瀏覽器 history state 供重新整理／登入後恢復，不寫入 query key、分析頁面事件或 API URL；GET 用 header、POST 用 body，no-store。預覽不透露購買者訂單 ID、地址、電話或帳號；只有實際領取者能查自己的結果。 |
| I8 | 既有訂單畫面提供本單禮包／贈禮入口；禮包頁有產生連結、複製／分享、撤回、已送出顯示。失去連結時明確重新產生，切換帳號清除暫存連結與前帳號結果。收件人沿用每日開盒元件與機率表。 |
| I9 | 新增 additive migration，不修改已套用 migration；既有自己領取、名片、每日 evergreen、物流／Admin、Points 恢復保持相容。新 migration 未自動套用遠端資料庫。 |

本次新擴充依 backend code-review policy 使用 L2 兩個獨立視角，最多 3 輪／2 批修正／6 次 reviewer 呼叫。以前五輪已交付的紀錄保留，不在此擴充重做或改寫其結論。驗證採隔離 PostgreSQL 與現有前台 jsdom，不操作正式配送、正式 DB 或鏈上狀態。
